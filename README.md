## 2. 游戏介绍

### 2.1 玩法内核

经典 3v3 半场对抗：双方各 5 座哨塔（3 座沿兵线、2 座守家）护卫己方源核，摧毁对方源核或触发硬上限即分胜负；
单条兵线横贯地图、野区提供增益与全局首领，装备与状态增益驱动滚雪球。加时进入衰竭阶段，
无视无敌强制结算，保证对局收敛。

### 2.2 地图与阵营

- 2:1 横向长方形战场，蓝方（左）与红方（右）关于中轴 `x = 0` **左右镜像对称**；兵线北侧贴边，南侧以实体石堤与野区隔开，5 处坡道开口连通。
- 纵向河道沿中轴贯穿，与兵线正交；桥面全速、浅滩减速并造成环境伤害。
- 野区含营地（树精 / 大型野怪 / 小型野怪 / 兵矿）与双方共用的征募井；**中央矿坑**为全局首领「渊卫」巢穴。
- 野区草丛提供视野遮蔽；己方只看见视野内与已探明区域（战争迷雾）。

### 2.3 中立目标与节奏

- **渊卫**（中央矿坑全局首领）：按队伍累计伤害归属，归属方获得 120 s 全队增益、赏金与战偶强化。
- **兵矿（辉矿）**：占领即全队收益，归属期间周期发放金币，直到被反占。
- 这些机制在保持现有地图布局的前提下叠加，不改变兵线 / 野区 / 河道结构（详见 `docs/07_PROGRESS.md` §1 / §5）。

### 2.4 表现层理念（MC 体素 / 零外部资产）

全部建模、纹理、图标、特效、音频均由代码生成，不引入任何第三方美术 / 字体 / 音频二进制；
唯一例外是运行时借用宿主 OS 中文字形（不随发布包分发，无字体时回退 ASCII）。
英雄、小兵、野怪、塔、源核、地形、技能与事件视觉统一为方块 / 像素化表达，
并随 `P-V0 → P-V4` 五阶段逐步细化（详见 `docs/06_VISUAL_SPEC.md` 与 `docs/07_PROGRESS.md` §2 / §4）。

### 2.5 合规与原创性

- 表现层无外部资产，`TC-COMPLIANCE-01/02` 门禁扫描源码与发布树；
- 命名、文案、机制均为原创，禁用词清单 `docs/TERM_DENYLIST.txt` 覆盖原作相关表达；
- 第三方版权资料隔离在 `LEGAL/`，不进入发布包、不用于生成商品化数值表。

## 3. 参与开发（构建与运行）

> 完整开发环境、工作空间划分与 CI 见 `docs/04_DEVELOPMENT.md`；下面是速查。

工具链锁定见 `rust-toolchain.toml`（Rust 1.99.1）。主要 crate：

| crate | 用途 | 对外二进制 |
|---|---|---|
| `game-core` | 共享组件、协议适配、确定性数学、战斗系统、地图数据 | — |
| `client` | Bevy 客户端：网络 / 输入 / 预测 / 插值 / 体素渲染 / 局内 UI | `gx-client` |
| `server` | Headless 战斗服务端（权威模拟） | `gx-battle` |
| `matchmaking` | `axum` 匹配服务（内存队列） | `gx-matchmaker` |
| `gx-net` | 纯协议层：版本协商、增量快照、幂等事件、传输抽象、视野策略 | — |
| `gx-config` | `ConfigSet`、内容 hash、结构校验、热更 | — |
| `gx-proto-content` | 自研占位内容表（英雄 / 技能 / 装备 / 目标 / 地图 / 经济 / 视野） | — |
| `gx-e2e` | 端到端与合规测试宿主 | — |

门禁与运行：

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --locked
cargo build --release --locked --workspace
```

```bash
# 终端 1：战斗服务端（UDP 0.0.0.0:5000，headless）
cargo run -p server --features offline-dev
# 终端 2：客户端（连接 127.0.0.1:5000）
cargo run -p client --features offline-dev
# 终端 3（可选）：匹配服务（HTTP :8080）
cargo run -p matchmaking
```

`offline-dev` 保留「单连接即开局」调试能力（PvE 单人对局即基于此），发布构建必须禁用（CI 门禁）。
