## 执行摘要（结论先行）

**核心结论：把《虚荣》作为"商业产品"进行 1:1 复刻，在法律上不可行、在商业上已被原作自身证伪、在工程上需要数量级为 100~200 倍于当前仓库的投入；但把《虚荣》作为"玩法参考"、以完全原创的 IP/美术/音频/命名去做一款移动端 3v3 MOBA，在技术上完全可行，且当前仓库已提供了一个正确的架构起点。**

五条决定性判断：

1. **法律是硬约束，不是可协商项。** 权利人 Super Evil Megacorp（下称 SEMC）在其《服务条款》IV.A 中把"角色、角色名、地点、地点名、故事、美术、动画、音乐、视听效果、角色形象，乃至 *methods of operation*（操作方法）"全部纳入权利主张，并声明保留**独占的衍生作品创作权**；其《Fan Content Policy》明确要求粉丝内容**必须免费或仅靠广告支持、不得收取任何费用**、不得使用商标/Logo、不得在域名与社交账号中使用商标、必须标注非官方免责声明，且权利人可随时撤销授权。[S4][S5] 仓库 `assets/README.md` 直接就是这份政策全文，并标注 "All Items Are Copyright 2017 Super Evil Megacorp"。[S25] 因此，**任何收费、任何使用 "Vainglory"/"虚荣" 名称、任何沿用原角色名与形象、任何暗示官方背书的商业发行，都不在授权范围内**。

2. **原作的商业结局本身就是最强的负面证据。** 2020-03-27 发行商 Rogue Games 突然关服，其公开致歉中直言"服务器成本是天文数字""我们花在服务器上的钱比大多数开发者做一整款游戏还多"；SEMC 数日后接管，关闭全部内购，把游戏改为 **client authoritative**（客户端权威）以削减服务器成本，并永久停用了好友、聊天、排行榜、组队、商店、活动等功能。[S3][S6] 中国大陆国服于 2020-07-28 10:00 停运。[S21] 这说明：**该玩法品类在"高保真画面 + 全球低延迟权威服务器 + 高强度实时对战"下的单位经济模型，历史上未能自负盈亏**。任何商业计划必须先回答"我们凭什么比原作更省、或更赚"。

3. **技术可行，但现状是"原型"而非"产品"。** 当前仓库约 6,500 行 Rust、4 个 crate、3 个二进制、约 15 个测试函数，已具备：60Hz 权威服务端、UDP/netcode 握手、快照广播、客户端预测与回滚对齐、一次完整的"技能→弹道→命中→伤害"闭环、程序化 3D 地图与 egui HUD。[S26] 但小兵生成/兵线、商店购买、多英雄、胜负判定、视野/迷雾、地形与寻路、账号体系、数据库、匹配集成、反作弊、真断线重连、ping/RTT、配置化、多平台全部为占位或缺失。[S25][S26] 详见 §4。

4. **"编码 vs 美工"是必要但不充分的划分。** 达到商业品质的工程量中，美术/音频约占 40%~55%，编码约占 30%~40%，其余 15%~25% 为策划数值、QA、运维/安全、法务合规、发行与社区（见 §10）。**只算"写代码"和"画图"会系统性低估一半以上的成本。** 单个英雄的完整美术资产（模型/绑定/25~40 段动画/10~20 个特效/音效/图标）量级为 2~4 人月；原作末期约 55 位英雄。[S22]

5. **推荐路线**：**L2 机制致敬 + 全原创表达**（定义见 §1.2）。保留"单线 3v3 + 野区 + 占领型中立目标 + 双出装体系 + 点触/摇杆双操作"这类**规则层**设计，重做全部**表达层**（名称、世界观、角色、地图美术、UI、音乐、音效、数值表），并把目标平台收敛到单一平台先行。这是唯一同时满足法律、成本、周期三条约束的路径。

**Go / No-Go 门槛**（必须全部满足才建议立项，详见 §13.2）：
- 书面法律意见确认"原创表达 + 规则借鉴"不落入 SEMC 权利主张范围；
- 完成垂直切片并以数据验证单位经济（单局服务器成本、目标 ARPPU、留存）；
- 明确放弃"官方复刻 / 虚荣精神续作"等一切蹭 IP 的市场表述；
- 完成仓库内第三方版权数据与命名的清理。

## 0. 研究方法与证据分级

### 0.1 方法
1. **原作事实核查**：以官网一手页面/公告/法律文本为主，行业媒体与数据聚合平台为辅，社区百科仅用于补充细节并显式标注低置信度；对存在冲突的事实单列分歧表（附录 C），不做静默取舍。
2. **现状基线**：对本地 workspace 做只读代码盘点（目录、依赖、逐文件系统清单、占位/死代码、测试覆盖、规模统计）。[S26]
3. **差距推导**：把原作系统拆成可验收的功能项，逐项标注"可实现性 / 归属工种 / 交付物 / 验收标准"，再自下而上汇总人月，并用自上而下的品类类比交叉校验。
4. **风险与合规**：区分"法律禁止"、"技术上不具经济性"、"商业生态不成立"三类不可行，避免把"难"说成"不能"。

### 0.2 证据等级
| 等级 | 含义 | 本文中的典型来源 |
|---|---|---|
| **A** | 权利人官方页面 / 官方公告 / 官方法律文本 / 政府法规原文 | 官网 Game 页、5v5 交互地图页、Community Edition 公告、Terms of Use、Fan Content Policy、国家新闻出版署通知 |
| **B** | 权威行业媒体、赛事数据聚合平台、主流财经/科技媒体 | GamesIndustry.biz、Pocket Gamer.biz、TouchArcade、Digital Chumps、Esports Earnings、Esports Charts、界面新闻 |
| **C** | 社区百科 / 玩家 Wiki / 转载 / 仅获得搜索摘要未取得正文 | 萌娘百科、Vainglory Fandom、VaingloryFire、Wikiwand 镜像、镜像博客、各类下载站转载的更新日志 |
| **D** | 本地工件 | 仓库 `README.md`、`assets/README.md`、`dictionaries/*.json`、`schemas/2.7/`、源代码 |

**规则**：凡数值随版本变化的机制细节（刷新时间、伤害、金币、英雄数量、地图计时）一律标注来源等级与适用版本；C 级数据不得单独作为数值设计依据。

## 1. 目标界定与范围

### 1.1 必须先回答的问题
"复刻《虚荣》"在工程上是歧义的。不同解读对应完全不同的法律结论、工作量与预算，若不先界定，任何可行性结论都无意义。

### 1.2 四层复刻定义

| 层级 | 定义 | 使用原作表达性资产 | 商业发行 | 本文结论 |
|---|---|---|---|---|
| **L0 私服/模拟复现** | 复现客户端与服务端行为，使用原名称、原角色、原地图、原资源 | 是（且通常需逆向原客户端/协议） | 否 | **不可行**：违反 ToU IV.A 与 Fan Content Policy；涉及规避技术保护措施与 DMCA 反规避风险 [S4][S5] |
| **L1 1:1 商业复刻** | 逐系统、逐数值、逐角色对照重做，但代码自写 | 是 | 是 | **不可行**：法律禁止（§3）；且需巨额资产投入（§10） |
| **L2 机制致敬（推荐）** | 借鉴规则层设计（3v3 单线+野区、占领型中立目标、WP/CP 双出装、点触操作、20 分钟对局节奏），**全部表达层原创** | 否 | 是（需法律意见背书） | **条件可行**：技术无障碍，成本可控，是本文推荐路线 |
| **L3 品类借鉴** | 只做"移动端 MOBA"，不刻意对齐《虚荣》特有机制 | 否 | 是 | **可行**：法律最干净，但差异化与立项理由需重新论证 |

### 1.3 本报告的"商业级"验收口径
本文以"可上线运营的付费产品"为标准，至少包含：账号与实名、权威服务器与反作弊、匹配与排位、可用商店与经济系统、≥12 位可用英雄、可玩性验证（留存/付费/崩溃率）、多机型适配、客服与运营后台、合规资质、可回滚的发布与热更能力。**仅"能联机跑一局"不计入商业级。**

### 1.4 不在范围内
- 对 SEMC 未公开技术（引擎源码、服务器实现、 netcode 细节、资产管线）的逆向或推测；
- 具体法律结论、侵权判定、赔偿测算；
- 具体投资回报、市场规模数字（缺乏经审计的一手数据，本文只做定性判断）；
- 原作各版本完整数值表复原（数值随版本剧烈变化，且属表达性内容，不建议逐项对齐）。

### 2.4 玩法系统：5v5「风暴高地 / Sovereign's Rise」

Update 3.0 引入三路地图与真实视线迷雾（true line-of-sight Fog of War）。[S15] B 官方交互地图页列出的机制（A 级）[S2]：

- **Blackclaw Rush**：中路英雄可借河流水流更快支援边路；
- **River Shops**：河道两端的河岸商店；
- **Goldoak**：击杀给 **200 金币 + 35 经验**；
- **Crystal Treant / Weapon Treant**：掉落可掉落、可被敌方拾取的能量球，分别提供 **+20% 法术伤害与 10% 法术吸血** / **+15% 物理伤害与 2 秒衰减减速**；
- **Healing Treant**：12 秒内按等级回复生命与能量；
- **Teleport Boots**：可传送到己方塔、侦察相机（Scout Cam）或小兵，落地获得加速；
- **Armories（军械库）**：摧毁可削弱/消除敌方 Vain Crystal 的防御并强化己方兵线；
- **Halcyon Missiles / Rupture Cascade**：Vain Crystal 自卫机制（追踪导弹，数量随剩余 Armory 数；以及造成眩晕的爆炸线）；
- **Blackclaw / Ghostwing**：中期首领级中立生物，捕获后分别推塔灼烧 / 为全队提供脱战再生护盾；

### 2.5 英雄、定位与出装

官网 Game 页的官方职业分类（A 级）[S1]：**Assassin（刺客）、Mage（法师）、Protector（守护者）、Sniper（狙击手）、Warrior（战士）**，每位英雄标注推荐分路 `Lane` / `Jungle`，并标注 `free`（当周免费英雄）。玩家社区与攻略体系另有职能分工：**Captain（队长/辅助）、Carry（核心输出）、Jungler（打野）、Roamer（游走）**。[S10] A / [S45] C

**双出装体系**是《虚荣》最具辨识度的规则设计：
- **WP / Weapon Power（武器强度）**：强化普攻与物理向技能；

### 3.5 中国大陆上线合规（若面向国内商业发行）

依据国家新闻出版署通知与《未成年人保护法》相关条款 [S24]：

- **版号**：网络游戏须经依法审批后方可运营（《未成年人保护法》第七十五条）；无版号不得商业化运营、不得开启付费。
- **实名注册与登录**：所有用户须以真实有效身份信息注册并登录；须接入**国家新闻出版署网络游戏防沉迷实名验证系统**；**不得以任何形式（含游客体验模式）向未实名用户提供游戏服务**（国新出发〔2021〕14 号）。当前仓库使用 `ClientAuthentication::Unsecure`、无账号体系，与这一要求差距为零基础起步。[S26]
- **未成年人时长与付费限制**：仅周五/周六/周日及法定节假日 20:00–21:00 提供 1 小时服务；须设置时间管理、权限管理、消费管理功能；须做适龄提示与内容分类。[S24]
- **数据与隐私**：个人信息收集最小必要、单独同意、可查询/更正/删除、跨境传输需合规路径；当前仓库无任何隐私政策、无数据留存策略。[S25][S26]
- **内容合规**：角色形象、皮肤、文字、语音、聊天内容需过审；含 PvP 聊天与 UGC 需内容安全机制（当前协议定义了 `Chat`/`Ping` 但无实现与审核）。[S26]
- **支付与渠道**：需对接合规支付、渠道分成、发票与税务；涉及随机抽取（宝箱/蓝图类）需符合概率公示等规范。

> 工程含义：§3.5 的每一项都是**编码工作**（账号中心、实名认证对接、防沉迷时钟、消费限额、内容审核、日志留存、审计后台），且必须在**立项架构阶段**预留，不能上线前补丁式追加。

### 3.6 结论
**L0 / L1 在任何收费场景下不可行；L2 可行但必须完成"表达层 100% 原创 + 命名与仓库清理 + 第三方数据处置 + 书面法律意见"四件事。** 建议在立项前由律师出具针对以下问题的书面意见：玩法规则借鉴的边界、"methods of operation" 条款在目标司法辖区的可执行性、独立创作证据链要求、遥测字典的权属与使用限制、目标市场的商标检索（FTO）。

### 4.5 差距倍率（工程判断）

以"商业上线最小集合"（§1.3）为分母：当前仓库覆盖了**网络同步骨架 + 一次战斗闭环**约 2 个子系统，占商业级系统清单约 **5%~8%**；按代码量类比，6.5k 行原型 → 商业级客户端+服务端+后台通常在 **30 万~100 万行**量级（不含引擎与美术资产），即约 **50~150 倍**。此倍率为品类类比估算，用于建立数量级直觉，**不是精确预测**。

## 6. 玩法系统逐项拆解：编码 vs 美工

> 本章回答"哪些是编码工作、哪些是美工工作"。每项给出交付物与**可验收标准**（工业级文档必须有验收口径）。WBS 编号用于 §9/§10 汇总。

### 6.1 规则与模拟层（纯编码 + 策划）

| WBS | 系统 | 归属 | 交付物 | 验收标准 |
|---|---|---|---|---|
| C-01 | 固定步长权威模拟（60Hz）、tick 时钟 | 编码 | `ServerTick`、确定性帧循环 | 同一输入序列重放得到一致状态；tick 抖动 < 1ms |
| C-02 | 移动/朝向/碰撞/寻路（含地形与草丛） | 编码 | 导航网格或几何碰撞、路径跟随 | 无穿墙、无卡死；1000 次随机路径成功率 ≥99.9% |
| C-03 | 兵线系统（波次、路点、攻防 AI、仇恨） | 编码 | `minion_spawn_system` 完整实现 | 每波按配置生成、沿路推进、正确被塔/英雄攻击 |
| C-04 | 野怪营地与刷新、金矿/兵矿占领状态机 | 编码 | 占领/归属/赏金分发/强化兵线 | 占领后全队金币与兵线强度按配置变化，可回滚 |
| C-05 | 中立首领（捕获计量、归属、推线 AI） | 编码 | 类 Kraken 目标（原创命名） | 最后一击归属正确、目标沿路推进、被击杀后可重生 |
| C-06 | 塔/基地/水晶、护盾、摧毁与胜负判定 | 编码 | 结构物状态机、`MatchEnd` | 摧毁水晶即结算；无兵线护盾逻辑正确 |
| C-07 | 伤害管线（物理/法术、护甲/魔抗、暴击、吸血、护盾、 fortified health 类机制） | 编码 | 可配置公式与事件流 | 数值与策划表一致；有单元测试覆盖边界（0/负/溢出） |
| C-08 | 技能框架（目标类型、投射物、范围、控制效果、位移、冷却、能量） | 编码 | 数据驱动 `AbilityDef` + 状态效果系统 | 新增技能不改核心代码；控制效果可叠加/驱散/免疫 |
| C-09 | 装备/商店/合成树/主动道具 | 编码 + 策划 | 物品数据库、购买/售出/合成、属性叠加 | 全链路幂等；并发购买不产生复制或负金币 |
| C-10 | 视野/迷雾（服务端裁剪） | 编码 | AOI + 可见性判定 | 客户端收不到视野外敌方实体；抓包验证无信息泄漏 |
| C-11 | 网络协议（AOI/delta 压缩/通道分级/优先级） | 编码 | 增量快照 + 不可靠通道 | 见 §7.5 带宽预算 |
| C-12 | 预测、回滚、插值、抖动缓冲 | 编码 | 现状重构 | 150ms RTT / 3% 丢包下无可感拉扯 |
| C-13 | 断线重连（状态恢复式） | 编码 | 会话令牌 + 快照/输入历史恢复 | 断 30s 内重连回到原对局与状态 |
| C-14 | 反作弊（输入合法性、速率、服务器校验、行为检测） | 编码 + 安全 | 校验层 + 审计日志 | 变速齿轮/改包/全图挂的基础攻击被阻断 |
| C-15 | 匹配、排位、MMR、battle-server 编排 | 编码（后端） | 服务化 mm + 分配器 | 分区匹配、健康检查、优雅排空 |
| C-16 | 账号/实名/防沉迷/支付/订单/风控 | 编码（后端） | 账号中心 + 合规对接 | 通过合规验收；游客模式不可进入付费 |
| C-17 | 运营后台、日志、监控、告警、热更、灰度 | 编码（SRE） | 配置中心 + 数据管道 | 可不停服改数值；关键指标有 SLO |
| C-18 | 观战、回放、赛后统计 | 编码 + 数据 | 录制/回放格式 | 可复现任意一局 |
| C-19 | 多平台适配层（输入、分辨率、性能分级、生命周期） | 编码 | 平台抽象 | 目标机型清单全部达标 |
| C-20 | 自动化测试 / CI / 可复现构建 | 编码（QA 工程） | `Cargo.lock`、CI、回归用例 | 每次提交全量回归；构建可复现 |

### 6.2 表现层（美术 / 音频 / UX）

| WBS | 资产 | 归属 | 交付物 | 验收标准 |
|---|---|---|---|---|
| A-01 | 世界观与美术圣经 | 概念美术 + 策划 | 风格指南、色彩/材质/比例规范、禁用清单（与原作可区分性审查） | 法务/主美双签；通过可区分性检查 |

| A-05 | 局内 UI | UX + UI 美术 | HUD、小地图、技能栏、商店、计分板、目标提示、信号/Ping、结算 | 多分辨率/多语言/安全区适配；点击热区 ≥ 44dp |
| A-06 | 局外 UI | UX + UI 美术 | 登录、大厅、匹配、英雄选择、加载、商城、背包、战令、社交、设置、客服 | 与 C-16 后台字段一致；可 A/B |
| A-07 | 皮肤与商业化视觉 | 美术 | 每套皮肤模型/特效/图标/展示动画 | 不影响命中判定与可读性 |
| A-08 | 音乐与音效 | 音频 | BGM、局内环境、UI 音、技能音、语音、多语言 | 响度标准化；无第三方版权瑕疵 |

**关键的分工结论**：
- **编码负责"规则是否存在且正确"**，验收靠自动化测试与回放；
- **美工负责"规则是否被玩家看懂、是否被相信"**，验收靠可读性测试、机型实测与风格审查；
- 二者之间存在**接口契约**（动画事件帧、命中盒、特效挂载点、UI 数据字段），这属于**技术美术 / 技术策划**，是项目最容易漏算的岗位；
- 另有第三类工作不可归入二者：策划数值、QA、SRE/安全、法务合规、发行/社区/客服、数据分析（§10.1）。

### 6.3 原作特有设计的"是否建议照搬"

| 原作特性 | 建议 | 理由 |
|---|---|---|
| 单线 3v3 + 野区（快节奏约 20 分钟） | **建议借鉴** | 差异化明确、对局时长适合移动端、服务器成本低于 5v5 |
| 点触操作为默认 | **谨慎借鉴** | 是原作"硬核、劝退新玩家"的公认原因之一 [S34]；建议摇杆默认、点触可选 |
| 占领型中立目标（金矿/兵矿/Kraken） | **建议借鉴规则，重做表现** | 提供非对线的团队目标，是玩法核心乐趣 |
| WP/CP 双出装 | **建议借鉴规则** | 显著提升单英雄可玩深度，但平衡成本翻倍 |
| 天赋系统 / 蓝图 / 卡片合成 | **不建议照搬** | 反复改制引发明显负面舆情 [S50][S52]；且易触碰付费合规 |
| 5v5 三路 + 真实视线迷雾 | **二期再考虑** | 地图/英雄/匹配池/服务器成本全面翻倍，且同质化竞争激烈 |
| 全球跨平台同服 | **不建议一期** | 需多区域部署与输入公平性设计；单位经济未验证前不宜扩张 |
| 自建电竞赛事 | **不建议** | 原作生态 2018 后已萎缩 [S16] |

## 7. 技术可行性详论

### 7.1 网络模型：现状与目标

| 维度 | 现状 [S26] | 商业级目标 |
|---|---|---|
| 权威模型 | 服务端权威（正确方向） | 保持；但**视野裁剪必须在服务端**（现状全量下发 = 天然全图挂） |
| 模拟频率 | 60Hz FixedUpdate | 保持；补 tick 对齐、时钟漂移处理 |
| 上行 | `InputCmd`（Unreliable），`ping` 写死 0 | 输入序号/时间戳、RTT 估计、冗余输入重发、输入合法性校验 |
| 下行 | `WorldSnapshot` + `GameEvent` **全量 ReliableOrdered** | 基线快照 + delta、按通道分级（状态 Unreliable + 关键事件 Reliable）、AOI 裁剪 |
| 客户端 | 预测 + 硬/平滑修正；**插值插件未挂载** | 挂载插值；补抖动缓冲、外推上限、本地玩家延迟补偿 |
| 会话 | 断线后换新 client_id 重建、生成新英雄 | 会话令牌 + 状态恢复式重连 + 掉线托管/投降规则 |
| 安全 | `Unsecure` 认证、无 token | 认证网关、DTLS/加密、协议版本协商、限流与 anti-DDoS |
| 编排 | 单机、地址硬编码、1 人即开局 | 分区部署、battle-server 池、优雅排空、健康检查 |

> **反例警示**：SEMC 在 Community Edition 中为了削减成本把游戏改成 **client authoritative**，代价是数据存本地、卸载即丢失。[S3] 商业付费产品不能这么做——一旦客户端权威，付费数据与排位可信度即不可保证。**这是"技术选择直接决定商业模式是否成立"的典型案例。**

### 7.2 带宽量级估算（用于可行性判断，需压测验证）

假设 3v3 单局动态实体约 50~80（英雄 6 + 双方小兵若干 + 塔 10~12 + 野怪 ~12 + 弹体），服务端 60Hz 模拟、快照下行 20~30Hz：

- 单实体全量字段（net_id 4 + type 1 + pos 12 + rot 8 + hp 4 + energy 4 + level 1 + gold 4 + cooldowns 16 + flags 2）≈ **56 B**；
- 量化 + delta 后按 **24~32 B/实体** 估；
- 30 Hz × 80 实体 × 32 B ≈ **77 kB/s/客户端 ≈ 0.6 Mbps**；
- 10 人房 + 协议头/加密开销 ×1.5~3 ≈ **9~18 Mbps 出口/房间**（服务端侧）；
- 现状"全量 ReliableOrdered、无 delta"约为上述 **2~4 倍**，且可靠有序通道对实时状态会造成队头阻塞——这正是必须改造的点。

结论：**带宽不是不可行的瓶颈，架构才是**。真正的难点是"服务端视野裁剪 + 反作弊 + 大规模房间编排"，不是每秒多少字节。

### 7.3 性能与跨平台

- 官方宣传 60 FPS / 1.3M 多边形 / sub-30ms 触控响应 [S1]，是 2014 年 Apple 发布会级的技术标杆，需要引擎级优化（Metal 深度利用）[S27][S31]；
- Bevy/wgpu 在桌面可达，但要覆盖中低端 Android/iOS，必须做：材质与着色器变体收敛、纹理压缩（ASTC/ETC2）、LOD 与合批、动态分辨率、机型分级配置、启动时间与内存预算、后台/前台生命周期、热更新；
- `renet2_netcode` 依赖原生 UDP socket，README 已把 Web(wasm)/Android/iOS 标为"待改造" [S25] → 移动端原生 UDP 可行，wasm 需换 WebTransport/WebRTC 数据通道或改用 WebSocket 网关；
- 跨平台同服还要解决**输入公平性**（点触 vs 键鼠 vs 摇杆）与**帧率差异**，需产品规则而非纯技术。

### 7.4 后端与运维

当前 `matchmaking` 是内存 `RwLock` 队列、`MatchStore` 占位、客户端不调用它。[S26] 商业级需要：账号中心、数据库（关系型 + 时序/日志）、匹配服务（分区/分模式/MMR/超时扩池）、房间编排（battle-server 池、容量水位）、支付与订单、配置中心与热更、遥测与数据仓库、监控告警与 SLO、灰度与回滚、灾备。**这是与客户端同等量级的独立工程线**，常被原型阶段严重低估。

单位经济的关键变量（原作失败之处 [S6]）：单局服务器成本 = 房间时长 × (CPU/内存/出口带宽) / 每核并发房间数。**必须在垂直切片阶段实测该值**，并推导"每 DAU 服务器成本"，否则商业模型无法成立。

### 7.5 技术选型建议

| 选项 | 评价 |
|---|---|
| 继续 Bevy 0.20 + Rust 全栈 | **建议保留（L2 路线）**：服务端权威 + ECS + 无 GC 停顿 + 内存安全，对高频实时模拟是优势；现有 6.5k 行骨架可复用；团队已有积累 |
| 换 Unity/Unreal 做客户端、保留 Rust 服务端 | **备选**：若商业目标对"移动端 60fps 高保真 + 成熟资产管线 + 大量美术外包"权重更高，商业引擎的编辑器/资产商店/平台 SDK 会显著降低美术与适配成本；代价是双栈与共享逻辑重复 |
| 自研引擎 | **不建议**：原作自研 E.V.I.L. 是 2014 年 Metal 时代的历史选择；今天自研引擎的机会成本远超收益 |
| 保持 `bevy_egui` 做局内 UI | **仅限原型**：商业级局内 UI 需要动效、多分辨率/安全区、触摸热区、可访问性、本地化，egui 调试面板可留作开发工具，产品 UI 应重做 |

### 8.3 最容易低估的三件事
1. **动画与逻辑帧对齐**：命中判定发生在服务器 tick，动画命中帧、特效播放、音效触发必须与之对齐，否则"手感不对"；这是技术美术工作，不是纯编码也不是纯美术。
2. **可读性与阵营辨识**：MOBA 团战中，玩家必须瞬间分清敌我、技能范围、控制状态；这需要大量的可读性测试与迭代。
3. **可区分性审查**：为了避开 §3 的法律风险，每个原创资产都需要与参考对象做"可区分性"留档，这会增加一轮评审与返工。

## 10. 团队、成本、里程碑

### 10.1 估算口径与假设（必须显式声明）
- 成本 = 人月 × 综合人力单价；综合单价含工资、社保公积金、办公与设备摊销、管理分摊。
- 假设单价区间（仅用于量级测算，需按实际城市/团队/外包报价校准）：工程师 **3.0~5.0 万元/人月**、美术 **2.5~4.5 万元/人月**、策划 **2.5~4.0 万元/人月**、QA **1.5~2.5 万元/人月**。
- 采用"自下而上 WBS 汇总 × 自上而下品类类比"交叉校验，误差带建议按 **±40%** 理解。
- **不含**：市场买量、IP/音乐外包、云服务与带宽（运营期）、版号与合规咨询、电竞赛事、渠道分成、税费、办公场地扩张、并购/授权费。这些在商业发行中常与研发成本同量级甚至更高。

### 10.2 三档目标对比

| 档位 | 范围 | 团队 | 周期 | 总人月 | 研发成本量级 |
|---|---|---|---|---|---|
| **P0 垂直切片（建议第一步）** | 1 张地图、3 位英雄、3v3 单机房间、核心战斗闭环、基础 UI、可测的单位经济 | 8~12 人 | 6~9 月 | 60~100 | **约 200~450 万元** |
| **P1 商业上线最小版（L2）** | 1 张地图、12 位英雄、完整玩法+商店、账号合规、匹配排位、反作弊、2 平台、运营后台 | 30~45 人 | 20~28 月 | 600~1,100 | **约 2,000~5,000 万元** |
| **P2 原作规模对齐** | 2 张地图、50+ 英雄、全模式、全皮肤体系、4 平台同服、全球多区域、观战电竞 | 60~120 人 | 36~48 月 | 2,500~5,000 | **约 1~2.5 亿元以上**（且法律不可行，见 §3） |

> P0 的必要性：原作失败于单位经济 [S6]。**在 P0 阶段就必须实测"单局服务器成本"与"留存/付费假设"**，若不成立，不应进入 P1。这是本文最重要的流程建议。

### 10.3 建议里程碑与 Go/No-Go 闸门

| 阶段 | 周期 | 交付 | 闸门 |
|---|---|---|---|
| M0 立项前 | 2~4 周 | 法律意见书、商标 FTO、仓库合规清理、目标机型清单、单位经济模型 | **G0**：法律结论为"可做"；否则终止 L1/L0 路线 |

| M2 垂直切片 | 4~6 月 | 3 英雄 + 完整一局（兵线/野区/占领目标/塔/胜负）+ 基础商店 + 基础美术 | **G2**：外部玩家测试留存与手感达标；单局服务器成本实测 |

| M5 正式发行 | — | 多平台/多区域 | 持续运营 |

### 10.4 商业可行性判断（定性）

**不利因素**：
1. 原作本身在商业上未成功：Rogue 明言服务器成本超过"多数开发者做一整款游戏"的预算，最终关服 [S6]；国服亦于 2020 停运 [S21]；行业媒体与社区普遍归因于点触操作门槛高、人气不足、商业化改制反复 [S21][S34][S50][S52]。
2. 市场格局已变：原作上线同期《王者荣耀》迅速占据国内移动 MOBA 头部 [S21]；今日移动 MOBA 已是成熟红海，新入局需极强差异化与买量预算。
3. 电竞窗口关闭：赛事奖金与收视在 2017 见顶后快速回落 [S16]，无法作为低成本获客手段。
4. 单位经济对服务器成本极度敏感（60Hz 权威 + 全球低延迟 + 反作弊），而收入依赖 F2P 长线留存。

**有利因素**：
1. 3v3 单线 + 占领型中立目标在当下仍是**差异化**设计，对局时长短、单局服务器成本低于 5v5 三路。
2. 规则层借鉴可显著降低策划试错成本；当前仓库已验证网络架构方向正确。
3. Rust 服务端在高频模拟、内存安全、单机并发密度上有成本优势，正好对标原作最痛的服务器账单。

**综合**：技术上可行，**商业上属于高风险、需以 P0 数据决策的项目**；不建议以"复刻《虚荣》"为立项理由，建议以"短局、高操作深度的移动端团队竞技"为产品定位。

## 12. 结论与建议

### 12.1 直接回答用户的四个问题

**哪些能实现？**
规则层几乎全部可实现：3v3 单线+野区、补刀经济、兵线与塔、占领型中立目标、WP/CP 双出装、点触/摇杆双操作、60Hz 权威同步 + 预测/插值、多英雄、商店、匹配排位、观战回放、跨平台、账号合规、反作弊——这些都是明确的编码 + 策划工作，且当前仓库已具备正确的架构起点。完全原创的美术、音频、UI、世界观也都能实现，约束只是成本与周期。

**哪些不能实现？**
- **法律上**：使用《虚荣》/Vainglory 名称与商标、原角色名与形象、原地图名称与景观设计、原 UI/音乐/音效/剧情/数值表，以及任何收费的"粉丝复刻"、任何官方背书暗示、任何逆向原客户端/服务端（§3）。
- **商业生态上**：重建 2016-2017 年的移动电竞生态与行业曝光窗口（§2.9）。
- **事实上**：以"复刻"之名获得与原作相同的市场地位——原作自身已停运（§2.1）。

**哪些是编码工作？** §6.1 的 C-01~C-20：模拟、寻路、兵线、AI、占领状态机、伤害管线、技能与状态效果、装备商店、服务端视野裁剪、协议压缩、预测插值、真重连、反作弊、匹配编排、账号实名支付、运营后台、观战回放、平台适配、CI。以及 §7 的架构改造与 §3.5 的合规工程。

**哪些是美工工作？** §6.2 / §8 的 A-01~A-10：美术圣经与可区分性审查、地图、每位英雄的概念/模型/绑定/25~40 段动画/10~20 个特效/音效/图标、小兵野怪塔、局内与局外 UI、皮肤、音乐音效、品牌与字体、本地化排版。**但必须补上第三类**：策划数值、技术美术（动画与逻辑帧对齐）、QA、SRE/安全、法务合规、发行与社区——它们约占商业级总投入的 15%~25%，且常是项目失败的直接原因。

### 12.2 推荐路线

> **立项为「原创 IP 的短局高操作深度移动端 MOBA」，把《虚荣》仅作为规则层参考资料，不做表达层对齐。**

顺序：M0 法律与合规清理 → M1 架构加固 → **M2 垂直切片并用数据验证单位经济** → G4 通过后再进入内容量产。任何"先做 55 个英雄 / 先做 5v5 / 先做全球同服"的排期都应被否决。

### 12.3 立即可以做的 7 件事（不依赖预算决策）
1. 执行 §3.4 的仓库命名与第三方数据清理；
2. 补 `Cargo.lock`、CI 与可复现构建；
3. 挂载已写好但未启用的 `InterpolationPlugin`；
4. 清理 `[DMG]/[SNAP]/...` 诊断日志与 `Unsecure` 认证；
5. 把硬编码地址/端口/数值改为配置，并把"1 人即开局"改为可配置的房间人数；
6. 把 `minion_spawn_system` / `jungle_spawn_system` 的 TODO 补成最小兵线闭环；
7. 建立参考版本快照文档（明确借鉴哪个版本、哪些规则、明确不借鉴哪些表达），作为法律"独立创作证据链"的一部分。
